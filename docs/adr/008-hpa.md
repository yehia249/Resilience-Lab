# ADR 008: CPU autoscaling policy

Status: accepted for implementation; verification is tracked in STATUS.md.

## Decision

Use autoscaling/v2 with a 60% CPU target, immediate +2/15-second scale-up and 120-second stabilized scale-down.

## Reason

CPU-based scaling is native and inspectable using metrics-server. Bounds prevent uncontrolled replica creation.

## Consequences

Single-node CPU capacity stays fixed. Pending pods and absent scale-up are valid results and must not be represented as successful scaling.
